# AI 号池管理器 · 使用说明

把多个 Codex / ChatGPT 订阅账号收进一个本地服务，对外只暴露一个地址和一把 Key。
可按额度和设置的优先级选择账号；Plus 普通网络错误不会触发账号切换。

**不需要安装 Python，不需要运行任何脚本，不需要改配置文件。**
Windows 双击 exe，macOS 打开 .app，剩下全在网页里点。

---

## v1.2.16：Plus 全部限额后的备用路径

在「系统设置 → Plus 备用路由」启用自动切换，为每个 Plus 模型选择一个已配置的
OpenAI/Responses 代理商模型。客户端仍选原来的 Plus 模型；全部启用的 Plus 账号
都确认额度耗尽后，网关改走该模型对应的备用路径。任一 Plus 账号恢复可用后，
新的请求自动回到 Plus。默认每 30 秒检查一次，可设为 15–300 秒。

页面显示原模型、备用模型、当前路径和额度检查结果；请求日志会记录真实目标及
切换原因，响应头 `X-AIPool-Route`、`X-AIPool-Requested-Model`、
`X-AIPool-Actual-Model` 也能区分 Plus 与备用。页面为全局路由状态；某把客户端
Key 必须同时授权原 Plus 模型及备用模型，未授权时会明确拒绝，不自动扩大权限。

没有启用的 Plus 账号、任意账号额度查询失败或状态未知，都不会触发备用；网络错误
和普通上游故障也不触发。若 Plus 请求返回 429，会在输出前重新核实一次全部账号额度。
额度检查不发送生成请求，但使用代理商备用模型可能产生该代理商的费用。

保存备用路径本身无需重启号池。已开始输出的流式回答继续原路径，不自动重放；
当前账号专属路由和备用通道均不支持 `previous_response_id`，遇到这种请求会提示开启新会话或发送完整历史。
关闭管理页面后后台仍会检查额度。没有配置备用的 Plus 模型维持原行为。

## v1.2.17：Plus 账号优先级

「系统设置 → Plus 账号优先级」可以调整 Plus 账号顺序，也可以把账号分组设为
自动、有 5 小时窗口或无 5 小时窗口。自动模式会优先使用上游明确返回 5 小时
窗口的账号；这些账号全部确认限额后，才使用没有 5 小时窗口的账号。额度恢复
后，后续新请求自动回到优先组。

账号一旦被选中，请求会固定到该账号的内部路由。网络波动、普通 5xx 或其它非
额度错误不会触发下一个账号；额度查询失败或状态未知也不会误用后备组。保存
顺序和分组不需要重启号池，但首次启用账号优先级或新增账号后需要重新启动一次
号池，让账号专属路由别名载入。页面会显示“尚未同步”时，不会自动退回普通轮换。

## v1.2.18：macOS 版与 Codex 模型目录冲突修复

新增 macOS 版本（Apple Silicon），使用方法见 [macOS说明](macOS说明.md)。数据保存在
`~/Library/Application Support/AIPool`，没有 Dock 图标，退出请用「设置 → 退出程序」。

「本机客户端 → Codex CLI → 写入并切换」会把其它工具（如 Codex Manager）在
config.toml 根级写入的 `model_catalog_json` 注释停用，原值保留在注释里。这个设置
会覆盖号池的模型目录，导致 Codex 缺少系统提示、回答不出自己是哪个模型。检测到
冲突时，卡片会显示「模型目录冲突」。

## v1.2.19：Windows 定时激活与 Plus 限额切换

在「系统设置 → 定时激活账号额度」可为选定的 ChatGPT Plus / Pro 账号创建多个任务，
设定简单问题和本机执行时间；支持每天重复或一次性执行。任务仅在管理器运行时执行，
会真实调用上游并消耗少量额度；Gemini 账号不在此功能范围内。

Plus 账号专属路由收到上游 429 后，会立即刷新额度并最多重试一次。若确认当前账号耗尽，
请求切到下一个可用 Plus 账号；若所有 Plus 账号确认耗尽，再按现有设置使用代理商备用模型。
普通网络错误、5xx 或额度状态未知不会触发切换。

## 一、启动

Windows 双击 **`AI号池管理器.exe`**；macOS 打开 **`AI号池管理器.app`**。

macOS 首次打开、数据备份及 Gatekeeper 处理见同目录 [macOS说明](macOS说明.md)。打包应用数据位于 `~/Library/Application Support/AIPool`，本文的 `data/` 路径在 macOS 上均指此目录（开发运行除外）。

- 首次启动会自动打开浏览器进入管理界面（默认 `http://127.0.0.1:8320`）。
- 端口被占用时会自动往后找一个可用端口，界面左下角会显示实际端口。
- 程序没有黑窗口。**关掉浏览器不等于关程序**，服务会一直在后台跑；要停就在
  「设置 → 退出程序」里点。
- 重复双击不会起第二份，只会把已有的界面重新打开。

## 二、第一次使用（三件事）

### 1. 配好出网代理

「设置 → 网络 → 出网代理」填上代理地址，例如 `http://127.0.0.1:7894`，点 **测试**，
看到「代理可用，HTTP 200」即可。

> 不填代理通常会被 OpenAI 判定为受限地区，请求返回
> `403 unsupported_country_region_territory`。

### 2. 添加账号

「账号 → + 添加账号」，先选**账号类型**，再选池。

**Codex（ChatGPT 号）**

1. 选择这个号要加入的池（Plus / Pro）；
2. 点「开始登录」，窗口里会出现一个 8 位设备码；
3. 点下面的链接打开 `auth.openai.com/codex/device`，输入设备码并登录；
4. 界面自动跳到「登录成功」，账号已加入号池。

**Gemini（Google 号）**

1. 池会自动切到 Gemini 池；
2. 点「开始登录」，窗口里出现一条 **Google 授权链接**；
3. 点开链接，选你要加的那个 Google 账号并同意；
4. 授权完成后自动落盘、自动归入 Gemini 池。

> Gemini 号走的是 Google 的 **Antigravity 通道**，用 Google 账号登录即可，
> 不需要申请 API Key，免费号和 Pro 号都能用。
>
> 如果浏览器提示「无法访问此网站」（回调打不回本机），把地址栏里那条完整链接
> 复制到窗口里的「回调地址」框，点「提交」即可。
>
> 登录成功后，号池会把上游真实可用的 `gemini-*` 模型名自动写进 Gemini 池，
> 不用自己猜模型名。

> 同一个池里的账号共用同一批模型名，自动互为备份。
> 新号登录后不需要重启服务。

### 3. 接上客户端

「客户端」页里复制 **Key**，再按同一页（或「概览 → 客户端接入」）给出的 Base URL
填到 Codex 或任意 OpenAI 兼容客户端：

| 项 | 值 |
|---|---|
| Base URL | `http://本机IP:端口/v1` |
| API Key | 客户端页里复制 |

Base URL 会给两条：

- **本机访问** —— `127.0.0.1` 那条，只在这台机器上能用；
- **局域网访问** —— 本机网卡地址（如 `192.168.1.23`），同网段的手机、别的电脑用这条。

端口取「设置」里的界面端口，界面上的地址是自动带上的，不用自己拼。同时连了多块网卡时，
第一块之外的地址会以小字列在下面，按需选用。

**Gemini 在 Codex 里能用哪些**：Flash 系（Gemini · 3 Flash、3.8 Flash、3.5 Flash Lite、
3.1 Flash Lite）已经进了 Codex 的模型目录，选中就能用，工具调用、流式都正常 —— 号池会把
Responses 请求转成 Gemini 协议。**Pro 档不行**：它的真实模型 `gemini-3.8-flash-tiered`
不在号池的注册表里，只有网关能直连 Gemini 原生接口（`/v1beta`），所以 Pro 只出现在
Gemini CLI 的模型列表里，选在 Codex 里会直接报“unknown provider”。

Gemini 也可以用下面的 Gemini CLI，或任意支持 Gemini 协议的客户端。

**用 Gemini CLI**：它读环境变量里的端点，地址**不要带 `/v1`**（它会自己拼 `/v1beta`）：

```powershell
$env:GOOGLE_GEMINI_BASE_URL = "http://本机IP:端口"
$env:GEMINI_API_KEY = "客户端页里的 Key"
gemini
```

**用 Claude Code**：它说的是 Anthropic 的 Messages 协议，网关同样能接。改
`%USERPROFILE%\.claude\settings.json`（用 CC Switch 的话，直接选「AI 号池（本地）」）：

```json
{
  "env": {
    "API_TIMEOUT_MS": "300000",
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:8322",
    "ANTHROPIC_AUTH_TOKEN": "客户端页里的 Key",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "pro-gpt-6.1-sol",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "plus-gpt-6.1-sol",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "gemini-3-flash"
  }
}
```

Claude 的模型菜单和 Codex 是**同一份表**：号池里有几个模型就显示几个，显示的名就是
真名（`Plus · GPT 6.1 Sol`、`Gemini · 3 Flash`、`Kakou · GPT 6.1 Sol` …）。

只有发给客户端的 **id** 得换个写法。Claude Desktop 的自定义供应商（3p）对 id 有**三**道校验，
规则都是从 `app.asar` 里抠出来的：

```
To   = sonnet|opus|haiku|fable|mythos
FCe  = ^(To)(-[\d.]+)?$                       纯档位名，如 sonnet-4.5
LCe  = ark-code|…|deepseek|…|gemini|…|gpt|…    黑名单
Do(id) = !LCe.test(id) && (FCe.test(id) || id 里含 claude/anthropic/档位词)

发现阶段： !Do(id) && !tier  → 丢掉        （带 tier 能绕过）
选模型阶段：Oo("gateway", id) → Do(id)      （绕不过）
思考档位：  Hon(id) = kon[id] ?? (id 以 fable-/mythos- 开头 ? 五档 profile : 无)
            没有 effort_options 时，界面上就叫「no effort menu for this model」
```

也就是说 `plus-gpt-6.1-sol`、`gemini-3-flash` 这种名字**一定会被客户端丢掉**；
而 `sonnet/plus-6.1-sol` 虽然能进菜单，却不在 `kon` 表里，**思考程度那一栏根本不会出现**。
另外每条还要带 `max_effort_level`，不写会被当成 `low`，档位就只能停在 Low。

网关的做法是「去掉黑名单词 + 挂 `fable-` 命名空间」，显示名保持真名：

| 菜单里显示 | 实际 id | 档位 |
|---|---|---|
| Plus · GPT 6.1 Sol | `fable-plus-6.1-sol` | Sonnet（默认） |
| Plus · GPT 6 Astra | `fable-plus-6-astra` | Sonnet |
| Plus · GPT 6 Sol | `fable-plus-6-sol` | Sonnet |
| Pro · GPT 6.1 Sol | `fable-pro-6.1-sol` | Opus |
| Pro · GPT 6 Astra | `fable-pro-6-astra` | Opus |
| Pro · GPT 6 Sol | `fable-pro-6-sol` | Opus |
| Gemini · 3 Flash / 3.5 / 3.1 Lite | `fable-3-flash` 等 | Haiku |
| Gemini · 3.8 Flash | `fable-3.8-flash-high` | Fable |
| Gemini · Claude Sonnet 4.6 | `claude-sonnet-4-6`（原样，自带档位表） | Sonnet |
| Gemini · Claude Opus 4.6 | `claude-opus-4-6`（原样） | Opus |
| Kakou / Sudo 那几条 | `fable-kakou-6.1-sol` 这种 | 按模型分 |

每个档位的第一条带 `is_family_default`，客户端按档位回退时就会选中它。

网关四种写法都认：真名（`plus-gpt-6.1-sol`，Claude Code 里手敲就行）、新菜单 id
（`fable-plus-6.1-sol`）、旧菜单 id（`sonnet/plus-6.1-sol`，1.2.0 的会话还在用）、
老的 `claude-*` 名（历史配置和后台小任务会发，按表翻，认不出的按档位兜底）。

**思考程度**：菜单里每个模型都有「Low / Medium / High / Extra / Max」五档，
选完会以 `output_config.effort` 发给网关，网关原样转给号池（号池认这个字段，
实测同一道题 low 出 19 tokens、max 出 71 tokens）。请求日志的「说明」列会记
`effort=max`，没带就说明客户端用的是默认档。

> 加完模型都用 `/v1/messages` 实打一遍，21 条全部 200。但「返 200」不等于
> 「背后是它自称的那家」—— 第三方号池转手过好几层，回包里的 `model` 字段和
> 自我认知都可能对不上。要确认货真价实，用「模型测试」页勾上模型跑一遍。

**Claude Desktop**：CC Switch 里那条「AI 号池（本地）」是 `proxy` 模式，写的是
`%LOCALAPPDATA%\Claude-3p\configLibrary\` 下的推理配置（网关地址 + Key，模型走
`/v1/models` 自动发现）。改完要退出 Claude 再打开，日志
`%LOCALAPPDATA%\Claude-3p\logs\main.log` 里会看到
`Model discovery: 21 found … picker = 21 (discovery)` 和
`ConfigHealth … state: 'healthy'`，就说明接上了。

> 两点限制：Pro 档的 `gemini-3-pro-preview` 只走 `/v1beta`（Gemini 原生协议），Claude 里
> 调不到；第三方通道的 Key 一旦被中转方拒掉（Kakou 的 GPT 那把、SudoCode 那把都是
> 这种情况），选它就会回「通道「X」授权失败」——去「设置 → 第三方通道」换 Key 立刻生效，
> 不用改模型列表。

## 三、日常操作

| 想做的事 | 在哪儿做 |
|---|---|
| 看服务是否正常 | 概览（左侧小圆点变绿＝号池就绪） |
| 看总调用量、成功率 | 概览 → 请求记录（成功/失败数 + 每天一格） |
| 看每个号跑了多少 | 概览 → 请求记录 → 各账号（每个号一条方块） |
| 看每个号还剩多少额度 | 账号与提供商 → 「剩余额度」列（进页面自动查） |
| 额度用完了想立刻恢复 | 账号与提供商 → 「额度重置」→ 用一次 |
| 接第三方中转站 | 账号与提供商 → 第三方提供商 → 添加 |
| 验证某个模型是不是货真价实 | 模型测试 → 勾账号和模型（提供商的模型也能测） |
| 重启号池 | 概览 → 服务控制 → 重启 |
| 停用某个账号 | 账号与提供商 → 把「启用」勾掉 |
| 换一个号登录 | 账号与提供商 → 删除 → 重新添加 |
| 改模型显示名 | 模型 → 改完保存，所有账号自动同步 |
| 给官方账号加模型 | 模型 → 池子右上角「+ 添加模型」→ 填上游真实模型名 → 保存 |
| 给不同人分配权限 | 客户端 → 新建 Key → 勾选允许的模型 |
| 开机自动启动 | 设置 → 开机自动启动 → 保存 |
| 让别的电脑也能管理 | 设置 → 管理口令 → 保存（不设则只允许本机） |
| 备份 | 整个 `data` 目录拷走即可 |

### 给官方账号加模型

「模型」页每个池子右上角有「+ 添加模型」，一行三个格子：

- **客户端看到的模型名**（alias）：`plus` / `pro` 池要以 `plus-` / `pro-` 开头（填了上游名会自动补），
  Gemini 池直接用模型名；
- **显示名称**：菜单里显示的文字；
- **上游真实模型**：号池真正发给上游的名字，输入框带候选下拉。

保存后网关会把别名写进这个池每个账号的凭据文件，并重启号池（约 3~5 秒），
客户端重新拉一次目录就能看到。

**为什么有的名字加了却不出现**：号池只接受「账号真的有权限」的上游名。名字写错、
或这个档位账号没有时，它会把这一条**静默丢掉** —— 表现是保存成功、列表里没有。
可以先用「模型测试」验一下，或看「概览 → 请求记录」里这条模型是不是 400 / 404。

也可以直接用 HTTP 接口（只允许本机或已登录管理界面），不用点界面：

```powershell
# 加：只给上游名，会自动生成别名 plus-gpt-6.1-sol
curl -X POST http://127.0.0.1:8322/api/pools/plus/models `
  -H "Content-Type: application/json" `
  -d '{\"name\":\"gpt-6.1-sol\",\"display\":\"Plus · GPT 6.1 Sol\"}'

# 删
curl -X DELETE http://127.0.0.1:8322/api/pools/plus/models/plus-gpt-6.1-sol
```

接口会把号池重启并**等它真的把模型列出来**才返回，所以不用自己等：

- `verified: true` —— 号池已经在 `/v1/models` 里列出这个模型，直接能用；
- `verified: false` —— 号池不认这个上游名（`hint` 里会说明），换一个再试。

请求体和返回示例：

```json
// POST 请求体：name 必填，alias / display 可省
{"name": "gpt-6.1-sol", "alias": "plus-gpt-6.1-sol", "display": "Plus · GPT 6.1 Sol"}

// 返回
{"ok": true, "alias": "plus-gpt-6.1-sol", "verified": true,
 "accounts_synced": 2, "restarted": true, "hint": ""}
```

几个已验证的上游名：

| 池 | 上游名 | 说明 |
|---|---|---|
| plus / pro | `gpt-6.1-sol`、`gpt-6-astra`、`gpt-6-sol` | ChatGPT 订阅档，**就这三个** |
| gemini | `gemini-3-flash`、`gemini-3.8-flash-high`、`gemini-3.5-flash-lite`、`gemini-3.1-flash-lite` | Antigravity |
| gemini | `claude-sonnet-4-6`、`claude-opus-4-6-thinking` | Antigravity 里的 Claude |
| gemini | `gemini-3.8-flash-tiered` | Pro 档，走网关直连（仅 `/v1beta`） |
| ✗ | `gpt-6.1-terra`、`gpt-6-luna`、`gpt-5.6-*`、`gpt-oss-120b-medium` | 号池不认，加了会 `unknown provider` |

> plus / pro 只有上面三个能用，这点是实测的：`gpt-6.1-terra` 曾经偶尔能通，但号池重启后
> 就变成 `unknown provider for model plus-gpt-6.1-terra`，不可靠，所以默认配置里已经去掉。
> 新加完模型，看一眼接口回的 `verified`：`false` 就是这个原因。

> Claude 侧只认 `claude-*` 路由名，新加的模型不会自动出现在 Claude 菜单里 ——
> 这是 Claude Desktop 的硬校验，不是配置遗漏。要让它出现，得在
> `core/gateway.py` 的 `ANTHROPIC_ROUTES` 里加一对「路由名 → 池里的别名」。
> Gemini 与 Codex 的列表会自动带上新模型（Codex 受 20 条上限约束，超出部分要用
> `-m 前缀/模型名` 手动指定）。

### 概览上的「请求记录」

一排 30 个方块，一格一天，从最早到今天（最后一格带蓝框）：

| 方块颜色 | 含义 |
|---|---|
| 灰色 | 那天没有请求 |
| 绿色 | 有请求，全部成功 |
| 橙色 | 有成功也有失败 |
| 红色 | 有请求但全失败 |

右上角是这 30 天的 **成功 / 失败** 总数，最右是 **成功率**。
鼠标停在任何一格上会显示当天日期和「成功 x · 失败 y」。

下面还有 **各账号** 一行一条：同样的 30 个方块，但只算落到这个号上的请求，
右边写这 30 天一共多少次。用来判断「是不是只有某个号在干活」「某个号是不是老出错」。

第三方供应商（如 Kakou）也占一行，按模型前缀 `kakou/...` 认领——
它们走的是 api-keys，没有账号凭据，所以不会出现在号池的账号列表里。

**下面这些不算「一次调用」，日志和统计里都不出现**（它们只是路过网关）：

| 情况 | 为什么不计数 |
|---|---|
| Key 无效（401 未知密钥） | 请求在网关当场被拒，压根没转发给号池 |
| 模型没授权（403） | 这把 Key 没勾选该模型，同样没转发 |
| 拉模型目录（`/v1/models`） | 只是查列表，没有调用任何模型 |

> 想看这些被拒的历史，去「日志 → 号池运行日志」，或者直接看客户端报的错——
> 它们属于「连都没连上」，混进成功率只会让数字失真。

> **怎么知道请求落到哪个号？** 号池在响应头里回一个 `X-Cpa-Trace-Id`，
> 第二段就是这次实际服务的账号标识，网关把它翻译成邮箱记进日志。
> 所以每条经网关的请求都能精确归到账号，不用猜。
>
> 只统计**经本机网关**上送的请求（客户端用你的 Key 调 `/v1/...`），
> 以及**模型测试**发出的请求（来源列显示「模型测试」）。
> 4xx 也算失败——多数是模型名写错、或这把 Key 没勾选该模型。
> 早期版本没记录账号，那部分历史认不出归属，不列在「各账号」里。
> 「今日请求」那张卡片下方同样会写今天的成功、失败数。

## 四、额度与重置

「账号」页的 **剩余额度** 列是实时向上游查的，不是本地估算：

- 每个号最多显示两个窗口：Plus 是「5 小时 + 7 天」，Pro 是「7 天」，
  Free 是「30 天」。进度条是**剩余**百分比，条变黄（<40%）、变红（<15%）就要留意。
- 下面一行写这个窗口什么时候刷新，例如「5 小时额度 3 小时 11 分后刷新」。
- 查询要出网，一次查全部账号约 2~3 秒；60 秒内重复进页面用缓存，
  点右上角「刷新额度」强制重查。

**额度重置** 列显示这个号攒了几次「立即恢复」的机会（OpenAI 时不时会送）。
点「用一次」会弹出确认框，里面写清楚当前用量、可重置次数和最早一张的到期日。

> 重置**不可撤销**，会立刻清空当前窗口并消耗一次机会。
> 确认按钮只在确实有可用次数时才亮。
> 到期时间越早的越该先用，过期就作废。

### Gemini 号的额度

Google 号的额度列写 **不限额 · 调用不扣**，这是实测结论，不是偷懒：

- 拿号池自己的 Key 打了三次真实请求（都落在同一个号上）：
  `gemini-3-flash` 普通（9 tokens）、`gemini-3-flash` 流式（237 tokens）、
  `claude-sonnet-4-6`（17 tokens）。
- 结果：**Gemini 的桶一点没动**（还是 1.0，`resetTime` 继续按「查询时刻 +5 小时」往后滚）；
  **Claude 的桶掉了**（`3p-5h` 0.9999608 / `3p-weekly` 0.9999804，`resetTime` 定格在请求时刻）。
- 结论：Antigravity 对 **Gemini 模型按「不限额」处理**（5 小时桶恒满、周桶根本不下发），
  只有 Claude / GPT 那组才真的计量。所以给 Gemini 画进度条只会得到一个永远 100% 的假数，
  旧版本就是这样，已经去掉了。
- 鼠标悬停在「不限额」上，能看到接口原样返回的全部桶和 12 个模型当前值。

**真实用量在哪看**：Gemini 客户端 / `gemini.google.com` → 设置 → 使用限额，
里面有「当前用量」（5 小时窗口）和「每周限额」两条。那套计量属于 Gemini 应用，
要走网页登录态，OAuth 令牌读不到，所以号池搬不进来。

> 应用那边用到 98%，不影响号池这边能不能发请求 —— Google 把 Antigravity 和
> Gemini 应用算作两套计量，互不顶替。号池这一列以前还会画「Claude / GPT 模型」那组，
> 也去掉了：Gemini 池只会把 Gemini 请求路由给这些号，那组永远不会被消耗。

如果某个号查不出来（token 过期、代理挂了），额度列会显示「查询失败」，
鼠标悬停有具体原因。号池重启一次会自动续期 token。

### Gemini 的 Pro 档（以及为什么没有 Argon）

账号上真正能调的 Gemini 模型，实测只有这些：

| 名字 | 结果 |
|---|---|
| `gemini-3.8-flash-tiered` | ✅ 200，**这才是 Antigravity 里「Pro」档发的模型**（1M 上下文 / 65K 输出 / 会思考） |
| `gemini-3-flash`、`gemini-3.5-flash-lite`、`gemini-3.1-flash-lite` | ✅ 200 |
| `gemini-2.5-pro` | ❌ 503「No capacity available」——免费档没有容量 |
| `gemini-4-argon` / `gemini-4-argon-disabled` | ❌ 404 `Requested entity was not found` |

Argon 不是配置问题：三个号的凭据里都只有一个 `gemini-4-argon-disabled` 占位名，
上游对它（以及去掉 `-disabled` 的各种写法）一律回 404，说明 Google 把这条路关了。

Pro 档走的是一条专用通道：号池代理（cli-proxy-api 8.0.40）的模型表里**没有** tiered，
写成 `model_aliases` 也会被静默丢掉（三种写法都试过），所以网关绕开代理，
直接拿账号的 OAuth 令牌打上游 `v1internal`（`core/gemini_direct.py`），失败自动换号。

Gemini CLI 里这些名字已经做好映射，选哪个都能用：

| 客户端发来的名字 | 实际走的模型 |
|---|---|
| `gemini-3-pro-preview` / `gemini-3.1-pro-preview` / `gemini-2.5-pro` | `gemini-3.8-flash-tiered`（直连） |
| `gemini-3-flash-preview` | `gemini-3-flash` |
| `gemini-3.8-flash` | `gemini-3.8-flash-high` |
| `gemini-3.5-flash` / `gemini-2.5-flash` | `gemini-3.5-flash-lite` |
| `gemini-3.1-flash-lite-preview` | `gemini-3.1-flash-lite` |

> Pro 只走 `/v1beta`（Gemini 原生协议）。OpenAI 兼容的 `/v1/models` 里不会列它，
> 免得别的客户端选了才发现调不通。

### Codex 的模型列表为什么是空的

Codex 拉完 `model_catalog_url` 后，会把每个模型按**内置默认值**补成一份完整定义
（系统提示词 21KB、确认策略 23KB…）。它有两个上限，踩到哪个都会出问题：

- **条数**：最多认 **20 条**。给 23 条时它只保留前 20 条；再多会让整份目录被丢弃，
  `/model` 里一个模型都没有 —— 不是网络问题，也不是 Key 问题。
- **体积**：20 条展开后约 0.9MB，已经贴着 1MB 的线。

号池以前把内部代理端口（8321）的 23 个模型原样丢给 Codex，正好踩线。
现在两头都改了：

- 客户端只连界面端口（如 `http://127.0.0.1:8322/v1`）；**8321/8318 是内部号池，别直连**，
  直连既绕过 Key 校验和日志，模型表还掺着图片模型、Gemini 模型这些 Codex 用不了的东西；
- 网关识别到 Codex 的目录请求（`originator: codex_cli_rs`）时，只返回能走 Responses 的模型，
  每条给的是精简字段，并且**硬性截到 20 条**（订阅池优先，第三方提供商排后面）。

> 换过端口、改过配置之后，把 `%USERPROFILE%\.codex\models_cache.json` 删掉再开 Codex，
> 让它重新拉一次目录 —— 这份缓存按 Base URL 分身份，旧地址拉空的缓存会一直复用。

### 「最近调用」列

左边一列写这个号**最近 3 小时**被用了多少次（号池按 10 分钟一次分桶统计）：

- 「全部成功」/「失败 N」是这个窗口内的情况；
- 「近 3 小时无调用」表示这段时间没轮到它；
- 号池认为这个号有问题时，这里会直接显示状态标签（如冷却中），悬停看原因。

> 这一列来自号池自己的运行时数据，**不消耗额度**，进页面自动刷新。
> 想查更长的历史就看「概览 → 请求记录 → 各账号」。

### 「订阅至」是什么日期

池名下面那一行是**订阅到期日**，取自账号登录时拿到的订阅信息：

- Plus / Pro 显示「订阅至 2026-11-22」这种具体日期，剩不到 7 天会变黄提醒；
- 免费号显示「免费号 · 无订阅期」（本来就没有订阅到期）；
- 拿不到订阅信息时退回显示「凭据至 xxxx-xx-xx」。

> 以前这里显示的是凭据文件里的 `expired`，那是**刷新令牌**的有效期
> （登录时给 10 天，每次续期往后滚），不是账号到期，看着会很奇怪。
> 现在显示的才是真订阅到期日；鼠标悬停能看到凭据本身的有效期。

## 五、第三方提供商（第三方接口）

这一块在「账号与提供商」页的下半部分（和订阅账号放在同一页，方便一起看），
管理 OpenAI 兼容的第三方接口：中转站、自建网关、别的厂商。

添加时填四项：

| 项 | 说明 |
|---|---|
| 名称 | 只是给人看的，例如 `Kakou` |
| 模型前缀 | 客户端看到的名字前缀，例如 `kakou` |
| 接口地址 | 一般是 `https://xxx/v1` |
| API Key | 服务商给你的 key |

再按行填模型，三列分别是：**别名**（客户端用的名字）、**显示名称**、
**上游真实模型名**（按服务商文档填）。填完可以先点「测试连接」，
能列出模型或能完成一次最小对话才算通。

启用后客户端看到的模型名是 `前缀/别名`，例如 `kakou/gpt-6-astra`，
和订阅账号的模型可以同时存在于一个号池里。

> 增删改都会**立即重启号池**，正在跑的请求会中断，建议空闲时操作。
> 多个提供商使用不同前缀就不会打架。

### Claude 类中转（重点）

中转站名字带 claude 的，协议和 OpenAI 那套不一样，有两个坑必须注意：

**一、模型名照抄 `/v1/models`，别按官网习惯写。**
不少中转把版本号写成连字符：上游返回 `claude-sonnet-5-5`，
你填 `claude-sonnet-5.5` 就会得到 `GROUP_MODEL_UNAVAILABLE`（503），
看起来像「服务挂了」，其实是名字没对上。列表里列了但实际没开渠道的模型
（例如某些站的 `claude-fable-5`）会回 `MODEL_NOT_FOUND`（404），删掉即可。
拿不准就直接请求中转的 `/v1/models` 看它给的是什么名字。

**二、协议会自动分家，不用你管。**
号池有两套上游通道：`codex` 走 `/v1/responses`（OpenAI Responses），
`claude` 走 `/v1/messages`（Anthropic 原生）。本程序按模型名自动判断：
**全部模型都是 `claude-*` 的提供商会注册进 claude 组**，混着 gpt 的仍走 codex 组。
塞错组的典型症状是请求卡 45 秒后 503（号池把 Messages 翻成 Responses
发到中转的 `/responses`，那边没有这个模型，重试 5 次全部失败）。
接口地址填 `https://xxx/v1` 或 `https://xxx` 都行，claude 组会自动去掉尾部 `/v1`。

想确认实际发给谁了，看 `data/pool/auths/logs/v1-messages-*.log`：
`Upstream URL` 是 `.../v1/messages` 且 `provider=claude` 就对了。

**三、中转自己回 401 时，网关会改写成 502。**
中转方拒绝你的 Key 时回的是 401 `INVALID_API_KEY` / `Invalid token`。如果原样转给
Claude 客户端，客户端会以为**自己的登录失效**（弹重新登录、把模型标成不可用），
看起来就像「这个模型不许用」。1.2.4 起统一改写成 502，并附一句人话：

```
通道「Kakou」授权失败（上游 401）：这把 Key 被中转方拒绝，请到「设置 → 第三方通道」更换
```

请求日志里仍然记上游真实状态码，便于核对。中转回的错误体也会被统一包成
Anthropic 形状（`{"type":"error","error":{...}}`），否则 Claude 界面上只剩一句 unknown。

**四、域名要写活的那个。**
SudoCode 的 `sudocode.chat` 已经解析到别人家的 IP 段（域名被停放），用
`api.sudorelay.com`。域名死活可以这样看：回结构化 JSON 错误（哪怕是 `Invalid token`）
说明服务活着，只是 Key 不对；连接超时 / 502 才是域名或服务没了。

## 六、模型测试（ModelTrace）

这一页回答一个问题：**我请求的这个模型名，实际服务我的到底是哪个模型？**

原理（来自 [ModelTrace](https://github.com/xqy2006/ModelTrace)）：让模型凭
「第一反应」输出一长串 1~355 的整数，不同模型在这个无语义任务上的数字分布
和先后顺序有稳定差异。把这些数字做成特征，和指纹库里每个模型的中心比相似度，
softmax 成概率。

用法：

1. 左侧勾账号（可多选），右侧勾模型（可多选）；
2. 右侧有两组模型：**订阅池模型**按「账号 × 模型」逐个跑，**提供商模型**
   用提供商自己的地址和 Key 直连（不需要选账号，只勾模型就能测）；
3. 点「开始测试」，结果实时刷新；
4. 看结果表的 **来源**、**判定模型**、**概率**、**结论**。

> 提供商模型这一组专门用来核对中转站：勾一个 `kakou/gpt-6-astra`，
> 工具会直接拿你填的地址和 Key 去问，看它实际回的是不是 astra。
> 同一行可以混着勾账号和提供商模型，会按顺序一个个跑。
> 提供商还没填 Key 的模型会显示「未配 Key」并且不能勾选。

模型名右侧的标签很关键：

| 标签 | 含义 |
|---|---|
| 库内 | 这个模型在指纹库里，判定一致/不一致可以当结论 |
| 库外 | 库里没有它，只能给出「最接近谁」，**不能**据此断言被换模型 |

结论分五档：

| 结论 | 说明 |
|---|---|
| 一致 | 判定模型与请求模型同名，概率越高越可信 |
| 基本一致 | 名字同族（前缀包含关系） |
| 档位一致 | 库里没有请求的模型，但最接近的那个和它同一档位 |
| 库外模型 | 库里没有；若指纹和某个库内模型几乎重合，会提示「值得核实」 |
| 判定不明确 | 前两名概率差距太小，不下结论 |

> 测试发出的请求**会计入调用统计**（日志里来源是「模型测试」、备注写提供商），
> 所以概览的方块会跟着涨——它确实消耗了账号额度。
> 每个组合消耗一次请求（约 300 个数字的输出）。
> **默认只发一条**，所以「概率」这一列的数字通常偏低（50%~70% 很正常），
> 只要判定模型同名就说明对得上；想让数字更硬，勾「每项测 3 条」——
> 会发三条不同长度的挑战、把结果合并打分，
> 官方数据显示这能把准确率从 96% 提到接近 100%，代价是耗时约 3 倍。
> 指纹库会更新，点右上角「更新指纹库」可以从上游拉最新的一份。
> 拉到的新库存在 `data\modeltrace\` 下，覆盖安装不会被换回旧版；
> 没更新过就读安装包里自带的那份（界面右上角会标「内置」）。

## 七、文件说明

以下目录结构适用于 Windows；macOS 使用完整 `.app`，数据单独存放在 `~/Library/Application Support/AIPool`。迁移电脑时需同时迁移该数据目录。

```
AI号池管理器.exe     ← 唯一要双击的文件
_internal\           ← 运行库和内置程序，不要删改
data\                ← 你的全部数据（配置、账号、日志、数据库）
  settings.json        设置
  pool\config.yaml     自动生成的号池配置，不要手改
  pool\auths\          账号凭据（等同于密码，别外发）
  logs\                运行日志
  modeltrace\          更新过的指纹库（没有就说明还在用包里自带的）
  pool.db              客户端 Key 与请求记录
```

> **exe 和 `_internal` 是一体的。** 只把 exe 单独拷到桌面（或者拷进别的
> 文件夹）会弹 `Failed to load Python DLL`，因为运行库没跟过去。
> 要挪位置就整个文件夹一起挪。

Windows 换电脑时：整个文件夹拷过去即可，账号和 Key 都在 `data` 里。

## 八、常见问题

| 现象 | 原因与处理 |
|---|---|
| 双击没反应，也没有浏览器弹出 | 大概率已经在运行，重复双击只会把已有界面重新打开；看浏览器是否已开着别的标签页 |
| 弹窗 `Failed to load Python DLL` | exe 被单独拷出来了，旁边缺 `_internal`。把整个文件夹一起拷，双击文件夹里的那个 exe |
| 记不住界面地址 / 端口好像变了 | 看界面左下角「界面 xxx · 号池 xxx」，或打开 `data\logs\app.log`，最后几行会写实际端口 |
| 提示「检测到程序已在运行，但界面没有响应」 | 上次进程卡住了；按提示的进程号到任务管理器（macOS：活动监视器）结束它，再双击打开 |
| 界面能开，但号池显示「已停止」 | 概览 → 启动；仍失败看「日志 → 号池运行日志」 |
| 请求返回 502 | 号池没起来，或代理不通，先点「启动」再测代理 |
| 请求返回 403 unsupported_country | 代理没开或出口不对，换一个能出国的节点 |
| Codex 模型列表是空的 | 模型名太多导致目录超 1MB；到「模型」页删掉不用的别名 |
| 所有模型都报错 | 账号可能都到限额了，看「账号」页额度条，必要时加号或用一次重置 |
| 额度列显示「查询失败」 | 多数是 token 刚过期，概览 → 重启号池让它续期，再点「刷新额度」 |
| 「用一次」是灰的 | 这个号当前没有可用的重置机会，等 OpenAI 再送或换号 |
| 模型测试结论是「判定不明确」 | 前两名太接近；勾「每项测 3 条」再测一次 |
| 模型测试提示没按要求输出数字 | 该模型拒答或截断，换模型/账号重试；连续失败说明这个号可能有问题 |
| 怎么确认推理档位（effort）真的生效了 | 看「日志」页「说明」列：`effort=max` 表示客户端确实发了这一档；空白表示请求里没带 reasoning，实际跑的是上游默认（通常是 medium） |
| 忘记管理口令 | 关掉程序，删掉 `data\settings.json` 里的 `admin_password` 那一行再启动 |
| 杀软/SmartScreen 提示风险 | 程序没有数字签名，个人小工具常见；确认来源可信后选「仍要运行」 |

## 九、安全提醒

- 管理界面默认**只有本机能打开**；设了管理口令才会对局域网开放。
- `data\pool\auths\` 里是账号的登录凭据，**泄露等于账号被拿走**，不要连同这个目录一起发给别人。
- 客户端 Key 可以随时停用或删除，停用后立刻失效。
- 本程序只在本机做转发和记账，不向任何第三方上传你的数据。
